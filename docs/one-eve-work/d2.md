## Producer bug

`me.tonsky.persistent-sorted-set.arrays/aset` returns a new persistent vector; it does not mutate its argument. Query_v3 still discarded those return values in tuple copy, output projection, constants, argument collection and scalar bindings. The same array contract exists at `22ea73167a`. Fixed those producers and consumers to thread persistent tuples, including join keys, product tuples and predicate argument construction.

Also removed redundant hand-written `->ArrayRelation`, `->CollRelation` and `->SingletonRelation` factories: Eve already generates them. On bb its constructor rewriting changed the manual factory's `Class.` call into a call to itself, producing StackOverflowError once query_v3 could load. Using the generated factories fixes this at its producer, with no host exceptions. This fixes the reported `#{[nil]}` output without changing the shared array API or adding target branches.

Regression: `test/eve_db_ds_query_v3_test.cljc`: actual Eve collection constructors/transients, simple projection, hash join, scalar/collection inputs, constants, predicate arguments and collection-source tuples.
