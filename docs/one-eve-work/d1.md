## Wire contract

The serialized value is a Clojure map with string keys; all arrays (including
keyword/value markers) are vectors. Both settings keys are mandatory on write.
This deliberately replaces the old cljs JavaScript objects/arrays and JVM
ArrayLists, not merely the crashing `amap-indexed` mutation. Existing callers
using JSON.stringify on raw JS objects must now convert the portable structure
at their JSON transport boundary. JVM and CLR restored indexes also follow the
same Eve vector-array conversion as the other targets.

`contract.serialize-portable` serializes the same two-entity DB on all four
hosts, checks representation and datom/structure round-trip, and emits a
canonical fixed-key-order `SERIALIZE-WIRE` line for byte comparison across hosts.
The canonical order is only for the regression output; map iteration order is
not part of the public wire contract.

## Numeric semantics

Exact numeric EDN (`N`, `M`, and ratio tokens) is encoded as `[1 <EDN text>]`
on every host, never deliberately rounded to a JSON double. This preserves
Clojure's existing representation and honors custom freeze/thaw functions.
A target that lacks an exact numeric type needs an exact `:thaw-fn`; accepting
an approximate JS double would not be Clojure-faithful. The default reader now
rejects a changed exact numeric token with `:serialize/exact-number` rather than
silently rounding. This is a loss-prevention guard, **not completion of the
requested universal exact-number semantic**. Eve needs a normalized exact
numeric representation/reader for hosts without the corresponding type. No per-host numeric
reader-conditional remains in this namespace. An nbb EDN-reader probe proved the missing producer support:

| input | nbb result before the guard |
|---|---|
| `9007199254740993N` | `9007199254740992` (precision lost) |
| `1/3` | `0.3333333333333333` (exact rational lost) |
| `1.2300M` | `1.23` (decimal type/scale lost) |

This gap must stay open even though #339's reader conditional is removed.
The portable driver additionally exercises exact numeric DB/wire round-trips
where the default reader preserves the token; unsupported targets must issue
the explicit guard error. These are reported as unsupported, not numeric passes.
